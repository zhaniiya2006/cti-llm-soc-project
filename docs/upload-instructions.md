# Загрузка исправленного проекта на GitHub

Репозиторий: [zhaniiya2006/cti-llm-soc-project](https://github.com/zhaniiya2006/cti-llm-soc-project).

Исправленная версия уже опубликована в `main` под аккаунтом `zhaniiya2006`. Повторно загружать текущий ZIP не требуется. Инструкция ниже пригодится для будущих обновлений или загрузки в другой репозиторий.

1. Распакуй ZIP через «Извлечь всё». Открой папку, где одновременно видны `README.md`, `Week1`, `week2`, `week3`, `week4`, `week5`, `docs`, `tests`, `tools`, `.github`, `.gitignore`, `.gitattributes` и файлы `requirements-*.txt`.
2. Войди в GitHub как `zhaniiya2006`. Открой репозиторий, вкладку **Code**, ветку **main** и корень списка файлов.
3. Выбери **Add file → Upload files**. Выдели всё содержимое распакованной папки (Ctrl+A) и перетащи его в область загрузки. Сохраняй каталоги целиком: отчёт должен оказаться в `week3/week3-report.md`, данные в `week3/data`, картинки в `week3/images`.
4. Проверь список перед отправкой: пути начинаются с `Week1/`, `week2/`, `week3/`, `week5/` и других каталогов проекта. Дополнительной внешней папки `cti-llm-soc-project-audited/` быть не должно. Текущий состав проекта описан в корневом README.
5. Укажи сообщение `Update weeks 1-5 and evidence`. Выбери **Commit directly to main**, если доступно, и нажми **Commit changes**. Если требуется новая ветка, создай её, открой pull request и после проверки объедини его в main. Файлы в другой ветке ещё не обновляют main.
6. Убедись, что отчёт Week 2 открывает все шесть картинок из `week2/images`. Если при обновлении старой версии остался дублирующий каталог `week2/week2`, удали только его через меню **⋯ → Delete directory**, предварительно проверив список файлов. В опубликованной исправленной версии этого дубля уже нет.
7. Открой корневой README и ссылки на отчёты пяти недель. В Week 3 должны отображаться три изображения, включая настоящий `03-misp-event-live.jpg`; в Week 5 — три настоящих скрина Kibana. Проверь открытие CSV, JSON, XML и Sigma-правила. Во вкладке **Actions** дождись успешной проверки опубликованного commit.

Week 3 находится в правильном каталоге; дубли из корня и старый каталог `week2/week2` отсутствуют. [Историческая проверка](https://github.com/zhaniiya2006/cti-llm-soc-project/actions/runs/37827090023) подтверждает исходную публикацию недель 1–4; текущий статус и новые доказательства описаны в [обновлении прогресса](progress-weeks1-5.md). Нельзя использовать старую зелёную проверку как подтверждение нового commit.

Загружай извлечённые файлы и каталоги. GitHub не распаковывает загруженный ZIP в структуру репозитория.

Порядок загрузки и удаления каталогов проверен по [GitHub Docs: upload](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository) и [GitHub Docs: delete directory](https://docs.github.com/en/repositories/working-with-files/managing-files/deleting-files-in-a-repository).
